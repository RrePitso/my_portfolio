iDelivery — Full Project Status (Updated)

Purpose & Context: Acting as both developer and business owner, I am building iDelivery, a WhatsApp-based delivery system. The MVP goal is to establish real end-to-end message flows between customers and drivers with minimal manual intervention.

Currently, only the customer side is connected to a real number; the driver side still uses a Meta test number (so you need admin permissions).

Infrastructure

  • Numbers: Driver number (personal/temporary, Phone ID: 1212056825332424) and Customer number (MTN SIM, real production infrastructure, Phone ID: 1279274528599243). Two separate WABAs independently subscribed under the same business.
  • Access & Auth: Permanent System User access token implemented to resolve the recurring 24-hour expiry breakage. Google Sheets writes utilize a service account and RAW input mode (fixing leading-zero stripping bugs).
  • Hosting: Auto-deploys from GitHub to the Render free tier (Frankfurt region) on every push.

Codebase Structure (src/)

  • server.js - Express, webhook verify + POST handler with diagnostic logging.
  • router.js - Routes by phone_number_id, passing WhatsApp profile names through.
  • customerFlow.js - Order-taking, confirmation, cancellation, and status checks.
  • driverFlow.js - Onboarding, main menu, accept/deliver, and payment note builder.
  • whatsapp.js - Graph API integration for sending text, buttons, and lists.
  • sheets.js - Google Sheets read/write operations for driver upserts and customer order lookups.

Feature Status

Fully Built & Tested (End-to-End):

  • Driver onboarding (auto-captures display name, stores payment preferences to Sheets).
  • New-order broadcast pinging all online drivers simultaneously.
  • Race-condition guard preventing double-acceptance of orders.
  • Customer payment notes displaying the assigned driver's accepted methods.
  • Verified full order lifecycle writing correctly to Sheets at each stage.

Built, Awaiting Live Test:

  • Order confirmation review step with edit capabilities.
  • Global cancel/restart commands mid-order.
  • Post-order action buttons and plain-language status checks.

Key Learnings

  • Permanent System User tokens are essential for production to avoid short-lived token breakages.
  • WABA webhook subscriptions and app publishing are silent failure points requiring direct verification.
  • Using USER_ENTERED in Google Sheets mangles numeric strings with leading zeros; RAW is the safer default for data backends.
  • Symmetric UX evaluation exposed friction in free-text customer flows when compared to button-first driver flows.
